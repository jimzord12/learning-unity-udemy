# Section 01 answers (check only after you attempted each question)

1. **Hub** manages Editor installs, projects, licences and sign-in. The **Editor** is the application you build the game in. The project's own file `ProjectSettings/ProjectVersion.txt` records the Editor version (yours: `6000.6.7f1`); the Hub reads it and opens the project with that version.
2. `Assets/` = your content (scripts, scenes, prefabs, art). `Library/` = generated import cache. `Packages/` = package manifest and lock file. `ProjectSettings/` = project-wide settings. `Logs/` = Editor logs. `Temp/` = scratch files. `UserSettings/` = per-user preferences. **Never commit** `Library/`, `Temp/`, `Logs/`, `UserSettings/` (and generated `*.csproj`/`*.slnx`). Your `.gitignore` already covers them. Commit `Assets/`, `Packages/`, `ProjectSettings/`.
3. A GameObject is an (empty) container in a scene. Components add behaviour or data to it (Mesh Renderer, Rigidbody, your scripts). Every GameObject has a **Transform** (position, rotation, scale).
4. Scene = edit the world (you move the camera freely). Game = what the player's Camera sees when playing. Hierarchy = objects in the open scene. Inspector = components/settings of the selected object. Project = files in `Assets/`. Console = messages, warnings, errors, `Debug.Log`.
5. Unity sees the old `.meta` without its file (it is removed) and a new file `Foo.cs` without a `.meta` (it generates a new one with a **new GUID**). Anything that referenced the old script by GUID (a prefab or scene component) loses the link, "Missing Script". Also the class name inside must still match the file name for a MonoBehaviour to attach. That is why you rename inside the Editor's Project window.
6. In the Editor's **Project window**, so Unity moves the `.meta` together with the asset and keeps GUID references valid.
7. In Unity: Edit > Preferences > External Tools > External Script Editor (choose Visual Studio Code). The Unity package `com.unity.ide.visualstudio` (you have 2.0.28) generates the project files; the VS Code Unity extension handles IntelliSense and debugging. Search: `unity vs code external script editor`.
8. Patch notes and downloads: unity.com/releases and the Unity Hub "Installs" tab. Project version: open `ProjectSettings/ProjectVersion.txt`. (Do not upgrade mid-course unless you do it on a git branch.)
9. It is a **warning**, not your code. It is printed by `com.unity.ide.visualstudio` when it cannot bind a UDP port for its "messaging" channel (used for Visual Studio / Unity communication). It does not stop you learning. See the diagnosis in the chat: on your machine the computed port 56838 falls in a Windows-reserved port range.
10. Unity **upgrade guides** for 6.0 -> 6.6 (`docs.unity.com/en-us/engine/6000.6/manual/upgrade-guides/...`) and the **6000.6 Script Reference**; then Unity Discussions and the course's Q&A. Always check the page's version.

**Rebuild challenge hints:** Transform = position/rotation/scale; Mesh Filter = which mesh; Mesh Renderer = draws it with a material; Box Collider = collision shape. Press Play and the cube should stay still unless it has a Rigidbody.
